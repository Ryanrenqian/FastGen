- FastGen config: `fastgen/configs/experiments/EDM/config_tfd_in64.py`.
- Seed 10; 200k optimizer updates (`trainer.max_iter=200001` under FastGen's exclusive loop bound); 7 training GPUs.
- Per rank: 10 class groups, 4 generated + 4 positive + 4 anchor images per group. Global generated batch: 280.
- Feature layers: `enc:6,enc:11,bottleneck,dec:7,dec:12`; pooling 4.
- Resolved modules: `enc/32x32_block1`, `enc/16x16_block2`, `enc/8x8_block2`, `dec/16x16_block0`, `dec/32x32_block0`.
- Radii: `[0.02, 0.05, 0.1, 0.2]`.
- Feature sigma: shared per class, truncated log-normal with `p_mean=-1.2`, `p_std=1.2`, `[0.02,0.1]`, 8 resamples.
- Conditioning sigma 80; AdamW $2\times10^{-6}$, betas `(0.9,0.999)`, weight decay 0.01; constant schedule with 500-step warmup; BF16 network compute (the official EDM calls this `use_fp16` but maps it to `torch.bfloat16`), no GradScaler; gradient clip 10; no EMA.
- Anchor margin: weight 1, alpha 0.5, temperature 1, bandwidth 0 (batch median).

### One-step FID evaluation

- Protocol: one student step from conditioning sigma 80, 50,000 generated images, seed 10, and 1,000 balanced ImageNet classes (global sample ID modulo 1,000; exactly 50 images/class).
- Metric: NVIDIA EDM/StyleGAN2-ADA Inception features. At the user's request, the initial fast evaluation uses a deterministic 50,000-image subset of the pinned ImageNet-64 training zip (seed 10), so it is reported as `FID-50k-subset` and is not directly paper-comparable.
- Samples are retained (`eval.cleanup_samples=False`) together with `fid.json` for auditability.

Reference-statistics command. FastGen's implementation uses NVIDIA's
`inception-2015-12-05.pt` detector and EDM accumulation/FID formula. Two attempts
to shallow-clone `NVlabs/edm` on the server failed with GnuTLS error `-110`, so
the versioned in-tree distributed entry point is used instead:

```bash

/root/miniconda3/envs/fastgen/bin/torchrun --standalone --nproc_per_node=8 \
  scripts/fid/compute_fid_ref.py \
```
